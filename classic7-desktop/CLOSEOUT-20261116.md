# iPod Classic 7 桌面模拟器：阶段交接包

日期：2026-11-16。用户要求本轮修复到此为止，整理并推送 GitHub，清理多余本地文件。**音频未完全修好；本文件不是修复完成声明。**收尾时重新检查，模拟器主程序、QEMU 和对应存储后端均未运行。本轮收尾不启动模拟器。

## 1. 项目目标

让原版 iPod Classic 7 固件在 Windows 桌面模拟器里正常运行，保留真实菜单、歌曲、设置和持久化虚拟磁盘，并通过电脑音频设备播放音乐。当前阶段重点是减轻播放卡顿、撕裂、进度跳秒和界面/游戏操作时的声音中断。

最后的用户听感反馈是“仍有，但明显减轻”。用户观察到过去无音频输出的版本没有同样的系统卡顿和跳秒；这一历史版本尚未完整重建做同条件对照。这里“系统”指 iPod 固件界面，而非 Windows。

R140 最后一段观测：`acceptance/realtime-20261116/r140b-120s.json`，120.013 秒，virtual/wall=1.000641，解码约 176582 B/s，电脑输出约 176449 B/s，标称 176468 B/s；**该窗口内新增** overflow/stale/empty callback 均为 0，最大补样间隔 13.2912 ms。此前累计计数并非全部为零。这只证明该两分钟的供样情况，不证明长期听感或交互负载合格。

当前曲目实测 MP3 解码 44100 Hz、模拟 I2S 44117 Hz、Windows 混音 48000 Hz。用户说导入音源最高 48 kHz，这是采样率，不是码率；不能推断整个曲库都是 48 kHz。匹配输出采样率本身此前没有消除供样不足。

## 4. 未完成任务，按优先级

以下仅供用户日后明确恢复任务时执行，本轮不继续实验。

1. 修正 R140 的可选对照测速器：基线/缓存路径必须对整个 `pl080_pace_request` 固定，不能每个剩余元素重选。现有结果 `baseline_calls=0`、`fast_calls=512`、`seen=1024` 无法算有效加速百分比。先补完整块边界用例，再进行有界对照。
2. 在同一曲目、同一计时配置下检查播放及菜单/Vortex 操作，关联音频空回调、DMA/解码耗时、补样间隔与虚拟时钟短时偏差。平均 CPU 约 0.2 核不能排除短时性能瓶颈，也不能证明有大量余量。
3. 真实听感和密集截图联合验收进度秒数/条形显示。R137 曾有 77 帧/7.838 秒单调进度样本；它不能否定用户报告的偶发 `0:11→0:13→0:12`。
4. 检查最新候选 Cover Flow、歌曲/设置保留、暂停/恢复/切歌。标准虚拟时钟曾出现低电量及真实 `SWRCON=aa5`，不能作为已接受默认配置；具体复位原因仍待证明。
5. 用户重新要求后再做自然睡眠/恢复验收。此前 SysInfo 容量与 PMU standby 路径虽已有修正，不能据编译或局部恢复证据宣布整个睡眠问题修好。

## 5. 关键约束、约定和坑点

- 不再使用 Cursor 云额度、DSH、Firecrawl；技术定位、代码和最终判断由主代理负责。若需 UI，由既有授权的 GPT-6 Luna low 执行并重新核对真实窗口；当前收尾没有 UI 操作。
- 始终只有一个后端写 K 盘 COW。重启/恢复前核对进程 PID、创建时间、路径、参数、文件哈希；历史 PID 不可复用。USB/Apple Devices 同步期间不能停止会话或操作 Hold。
- 不修改固件、guest PC/RAM/IRQ、不虚构 GPIO4 接线、不抬电量、不屏蔽 reset、不缩短或禁用睡眠，不碰实体磁盘。不要重复运行首次建盘工具。
- 正式文件维持固定 icount 的既有默认。用户允许独立候选测试 adaptive icount 和标准虚拟时钟；R140 实测使用 `auto,align=off,sleep=on`。`sleep=off` 已导致 UI 冻结，不作默认。
- TimerB IRQ8 是真实 1 kHz tick，不能为提高分数丢弃。R125 成对 warp/bias 记账健康，不再把它当欠推进根因。R135 后旧的“只有 70% 实时速度”数据不能代表新候选。
- native GDB 不调用 inferior function；只读脚本有界并安全 detach；不要用 `$ch` 等寄存器名作临时变量。侵入式采样会扰动时间，不能当听感验收。
- 导航键 Enter 确认、M/↑ 菜单、空格/↓ 播放暂停、←/→ 切歌、H 切换 Hold。不要把 W 当菜单。
- `received_fps=0`、静图或 WFI 不能单独判定睡死。旧截图遮挡/缓存曾导致误判。
- 历史自动写交接脚本、`launch140.ps1` 带旧 PID/状态或有缺陷的对照配置；不要直接重跑。本轮没有修改设备模型，也没有重新进行性能实验。
